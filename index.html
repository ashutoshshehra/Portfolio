JAVA WEB APPLICATION

AEGIS — Role-Based Access & Security Management

1. Overview & Rationale

AEGIS is a modular Java web application developed using Jakarta Servlets, JDBC, and MySQL. It was built to demonstrate clean multi-tier software architecture, separating responsibilities into presentation, service, and data access layers while implementing role-based access control (RBAC) and defensive database access.

⚠️
The Problem

Many beginner Java web applications intertwine SQL queries, business logic, and HTTP handling inside single servlet classes. This leads to code duplication, tight coupling, and vulnerabilities like SQL injection.

💡
The Solution

A structured multi-tier architecture with separate packages for Controllers (HTTP servlets), Services (business logic), and DAOs (JDBC PreparedStatement data access), protected by session authentication and role authorization.

2. System Architecture & Data Flow

Client Layer HTTP Client / Web Browser (HTML / Form Data / Requests)
↓ Requests dispatched
Controller Tier (`com.aegis.controller`) Jakarta Servlets • Request Validation • DTO Handling • Zero Direct SQL
↓ Invokes service methods
Service Tier (`com.aegis.service`) Business Rules • Role Verification • Domain Logic Orchestration
↓ Parameterized queries only
Data Access Tier (`com.aegis.dao`) JDBC `PreparedStatement` • Result Mapping to Models • Connection Release
↓ Connection pool
Database Tier MySQL Relational Schema (Tables, Foreign Keys & Indexes)

3. Key Engineering Features

  • Structured Exception Handling: Layered exception classes prevent raw database stack traces and internal paths from exposing details to client browsers.
  • Centralized Configuration: Configuration utility loading database credentials and app properties with environment fallback support.
  • Role-Based Access Control (RBAC): Session-level filters verifying user permissions before granting access to protected routes.
  • Unit Testing Suite: Automated test suites with JUnit and Mockito verifying service layer operations independently without live database dependencies.

4. Technical Challenges & Solutions

Challenge: Preventing Controller-DAO Coupling

Directly calling DAOs in servlets creates tightly coupled code. Solution: Enforced an explicit Service layer and DTO classes to decouple web handling from persistence.

Challenge: JDBC Resource Management

Unclosed connections can exhaust database connection pools. Solution: Implemented consistent try-with-resources patterns ensuring automatic closing of Connections, Statements, and ResultSets.

COMMUNITY PROJECT PROTOTYPE

AnnaSetu (AnnPath) — Food Redistribution Prototype

1. Overview & Mission

AnnaSetu ("A Bridge Between Food and Need") is a software prototype built to streamline food surplus redistribution. It connects food donors (banquets, caterers, restaurants) with verified NGOs and volunteer dispatchers, facilitating timely food claims before perishable items expire.

🍲
The Problem

Edible surplus food from events and restaurants often goes to waste due to the lack of an organized channel to notify nearby shelters and volunteers quickly.

🤝
The Solution

An authenticated web application with role-specific views for Donors, NGOs, and Volunteers, providing shelf-life countdown clocks, structured claim workflows, and real-time donation status updates.

2. System Architecture

Front-End Presentation JSP Views, JSTL, Responsive CSS, JavaScript Countdown Clocks
↓ Form submissions & requests
Filter & Controller Tier (`org.annpath.controller`) AuthenticationFilter • CharacterEncodingFilter • Role Route Filters • Servlets
↓ Business rules execution
Service Layer (`org.annpath.service`) Donation Workflow Logic • Expiry Status Checks • Claim Validations
↓ Transactional persistence
DAO & Database (`org.annpath.dao` / MySQL) PreparedStatement DAOs • Connection Pooling • Atomic Claim Queries

3. Key Technical Features

  • Multi-Language Support (i18n): Supported via Java ResourceBundle properties files for English, Hindi, and additional languages.
  • Shelf-Life Countdown Clocks: Synchronized expiration timers flagging listings approaching their expiry window to prioritize dispatcher routing.
  • Role-Based Navigation: Session security ensuring donors manage listings, NGOs claim available food, and dispatchers view assignments.
  • Dynamic Request Tracking: MySQL database tracking pending requests, active listings, and fulfillment history.

4. Technical Challenges & Solutions

Challenge: Preventing Double-Claim Race Conditions

Two NGOs attempting to claim the same food item simultaneously could cause duplicate claims. Solution: Implemented conditional SQL status updates within atomic transactions (UPDATE donations SET status = 'CLAIMED' WHERE id = ? AND status = 'AVAILABLE').

Challenge: Multilingual Character Encoding

Hindi Unicode script (Devanagari) was rendering distorted characters on older Tomcat setups. Solution: Implemented a custom CharacterEncodingFilter enforcing UTF-8 across all request and response streams.

WEB-BASED ONLINE EXAMINATION SYSTEM

SmartExam — Online Examination & Assessment System

1. Overview

SmartExam is a web-based online examination system built to manage online exams, questions, assignments, users, and examination results. Developed and tested locally using NetBeans IDE and GlassFish Server, it provides a structured platform for academic testing, allowing educators to create test papers and evaluate student performance through an intuitive web interface.

⚠️
2. Problem

Traditional paper-based examinations and manual evaluations require substantial administrative coordination, printing resources, and time-consuming manual grading. There is a need for a straightforward, localized web-based system where instructors can easily author questions, schedule tests, and compute student results automatically.

💡
3. Solution

An MVC web application providing dedicated interfaces for Admins, Teachers, and Students. The system centralizes question and assignment management, delivers timed tests to students, handles automated server-side evaluation, and stores all records in a structured MySQL database via JDBC.

4. User Roles & Responsibilities

  • Admin: Manages user accounts, oversees system activity, and maintains application integrity.
  • Teacher: Authors and edits questions, configures examinations and assignments, and views student results.
  • Student: Registers, logs in, browses available exams, takes timed assessments, and views instant evaluation results.

5. Key Features

  • Role-Based Authentication: Secure login workflows tailoring accessible views and features based on whether the user is an Admin, Teacher, or Student.
  • User Registration & Login: Account creation and credential verification with session tracking.
  • Question Management: Interfaces for adding, modifying, and organizing multiple-choice questions.
  • Exam & Assignment Management: Tools to create test papers, set time limits, and assign assessments to students.
  • Online Examinations: Clean exam interface featuring question navigation, option selection, and remaining time display.
  • Result Management: Server-side scoring comparing submitted responses to answer keys, with immediate performance feedback.
  • Session-Based Authentication: HTTP session control maintaining user state across pages and protecting unauthorized route access.
  • MySQL Database Integration: Standardized JDBC data access using parameterized PreparedStatement to store users, questions, exams, and results safely.

6. Technology Stack

  • Backend: Java, Java Servlets, JSP (JavaServer Pages), JSTL
  • Persistence: JDBC (Java Database Connectivity), MySQL Database
  • Frontend: HTML5, CSS3, JavaScript (DOM manipulation, timers, form handling)
  • Architecture & State: MVC (Model-View-Controller) Architecture, HTTP Session Management

7. System Architecture

User Roles Student / Teacher / Admin
↓ User interactions & form submissions
Presentation Tier JSP / HTML / CSS / JavaScript (Responsive Views & Client Timers)
↓ Dispatches HTTP requests
Controller Tier Servlet Controller (Request Handling, Route Protection & Session Management)
↓ Executes business rules & grading
Service & Business Logic Tier Service / Business Logic (Exam Scoring, Role Validation & Assignment Management)
↓ Parameterized SQL queries
Data Access Tier DAO / JDBC (`PreparedStatement` & Connection Management)
↓ Relational tables
Database Tier MySQL (Users, Questions, Exams, Assignments & Results)

8. Development Environment

  • IDE: Apache NetBeans IDE
  • Application Server: GlassFish Server
  • Database: MySQL Server (tested locally)

9. Future Improvements

  • Randomizing question and answer option order per student attempt to increase test variety.
  • Adding exportable grade sheets in CSV and PDF formats for teachers and administrators.
  • Supporting additional question formats such as true/false, fill-in-the-blank, and subjective questions.
